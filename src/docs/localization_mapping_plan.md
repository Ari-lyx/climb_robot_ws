# 球罐内定位与三维建图方案

日期：2026-09-16。状态：**方案草案，尚未实施**。

本轮只整理方案，不安装 SLAM 软件、不启动仿真、不修改 TF 发布器、RViz 或传感器配置。
下文的节点名、话题重命名、采样参数和验收门槛均为后续建议，不表示已经接入。

## 1. 先回答：世界视角需要 SLAM 吗？

**不需要。**当前已经有磁吸驱动插件发布的 `world → base_link` 动态 TF。
在 RViz 手动把 Global Options → Fixed Frame 从 `base_link` 改成 `world`，
并把 Views → Target Frame 设为 `<Fixed Frame>` 或 `world`，就能看到车体在世界中的
平移、倾斜、贴壁和倒挂。Orbit 的观察焦点还需放在罐体附近，而不是继续锁定机器人。

三件事需要区分：

| 项目 | 作用 | 是否需要 SLAM |
|---|---|---|
| RViz Fixed Frame | 显示数据最终变换到哪个坐标系 | 否，只需相应 TF 存在 |
| RViz Target Frame / 观察焦点 | 视角是否跟随机器人 | 否 |
| 估计机器人运动与地图 | 从传感器推算真实未知位姿、累积环境信息 | 需要里程计/定位/建图算法 |

Fixed Frame 为 base_link 时，车体在自己的坐标系中不动，所以看起来总是“水平”。
改为 world 不会改善定位精度，也不会自动生成地图；它只改变显示参考系。
MoveIt 的规划参考系和 RViz 的显示参考系也是两套设置，不能混为一谈。

**当前 `/odom` 是 Gazebo 真值**：`magnetic_drive.cpp` 读取 `base_->WorldPose()`，
消息父帧为 world、子帧为 base_link。它不是轮速积分，更不是雷达/相机里程计。
后续它非常适合做评估基准，但不能作为传感器定位算法的输入来证明算法准确。

## 2. 目标分层与推荐顺序

推荐路线：

**世界视角与数据检查 → 有特征场景的独立里程计基线 → 球罐退化实验 →
雷达/视觉路线选型 → 闭环三维建图 → 地图重定位 → 末端相机运动补偿。**

- 里程计：连续估计相邻时刻的六自由度运动，长时间可能漂移。
- 建图：把不同位置采到的数据变换、融合到同一个参考系。
- SLAM：在估计位姿的同时维护地图，可能通过回环修正累计漂移。
- 已有地图定位：利用事先建立的地图估计当前位姿，不必每次重建地图。

“先让定位靠谱，再建图”的工程顺序合理；但许多里程计前端本身就维护局部地图，
不是必须先完全解决全局定位，才允许开始建图。应先验收局部运动，再验收全局一致性。

第一版采用“移动时机械臂保持固定姿态、到点停车后用相机扫描”的工作方式。
定位全程保留 x/y/z、roll/pitch/yaw，不能将爬壁运动压成平面 x/y/yaw。

360×16 约为每帧 5,760 条采样射线，不等于有同样多有效返回点。
先检查当前数据是否足够；确有需要时再比较 5/10 Hz、不同水平采样数的精度与计算代价，
不要同时把雷达、相机和显示频率全部调高。

现有焊缝仅为视觉模型；当前 CPU ray 雷达不能依赖它们提供几何特征。
RGB/渲染深度可以看到什么、CPU ray 可以看到什么，必须分别检查。
球罐 STL 的多边形离散误差也可能提供虚假的定位线索，不能当作真实焊缝特征。

## 4. 球罐定位的两个核心难点

### 4.1 光滑球面与重复焊缝造成定位歧义

以下是结合当前场景的几何分析，不是某个算法已在本项目验证过的性能结论。

理想完整球面具有旋转对称性：仅靠距离观测，把轨迹绕球心旋转后仍可能解释同样的球面。
引入重力可约束倾斜方向，但不能提供绝对航向；短时陀螺积分也不能永久消除航向漂移。
局部只看到一小片壁面时，其形状又接近平面，切向运动容易缺少约束。
因此“配准误差很小”“地图很圆”不等于沿罐壁走过的位置是正确的。

半球开口、地面、管口、支撑件等可破坏部分对称性，不能把开口半球成功直接外推到
完整封闭球罐。规则重复的焊缝可能造成错误回环；磁吸机构和钢制罐壁环境下，
不要默认磁力计给出的航向可用，需按真实硬件实测。

建议用三组环境对照：

1. 有独特物体/纹理的普通三维场景：先证明接线、标定、时间与算法基本正常。
2. 有少量非对称特征的罐体：评估可识别特征实际带来的改善。
3. 光滑或重复纹理的球罐：明确失败边界，而不是不断调参掩盖不可观测方向。

若纯自然特征不足，备选是已知位置的视觉标记、可识别管口/结构件、球面先验和
带不确定性的轮速约束。标记可用性取决于现场能否布设；轮速不能忽略磁轮滑移。
几何先验能约束半径/壁面法向，却不能凭空确定沿球面的绝对位置。

### 4.2 末端相机不是刚性固定在车体上的相机

D435i 装在机械臂末端。机械臂动、底盘不动时，相机也会运动。
普通相机里程计首先估计的是相机运动，不能直接解释为底盘运动。

记 `T_A_B` 为将 B 坐标转换到 A 坐标的变换，则：

`T_odom_base(t) = T_odom_camera(t) × inverse(T_base_camera(t))`

`T_base_camera(t)` 必须来自同一采样时刻的关节状态与完整 TF 链，包含光学帧变换。
这只是位姿转换关系；速度、协方差、时延、运动模糊和相机杆臂效应还要单独处理。
不能仅把实时 TF 发布出来，就假设所有现成 VIO/LIVO 自动支持动态外参。

第一阶段锁定机械臂，确保相机—车体关系恒定。之后再单独验证：底盘静止时扫动机械臂，
估计的底盘应保持静止，地图不能跟着相机摆动。
车体 IMU 与移动末端相机不能直接套用“恒定外参”的视觉惯性配置；D435i 自带 IMU
虽与相机刚性连接，其仿真模型和真实标定仍需审计。第一版不做三传感器紧耦合融合。

## 5. 候选路线比较

| 路线 | 首先解决什么 | 优点 | 本工程主要风险 | 建议 |
|---|---|---|---|---|
| RTAB-Map ROS 2 的 3D ICP 里程计，再接建图 | 雷达数据/TF/配准基线 | 同一 ROS 2 工具链可逐步验证里程计与回环 | 光滑球面退化，稀疏点云，不能把普通 ICP 叫作紧耦合 LIO | 第一阶段雷达基线 |
| RTAB-Map RGB-D 里程计与建图 | 固定末端姿态下的视觉定位 | 可利用可见纹理，便于与雷达基线做 A/B 对比 | 弱纹理、反光、重复纹理、RGB-D 未配准、末端外参变化 | 与雷达分开测试 |
| FAST-LIO2 + 车体 IMU | 雷达—惯性紧耦合局部里程计/地图 | 支持旋转雷达和外部六轴 IMU，适合研究六自由度运动 | 逐点时间/去畸变、外参、ROS 2 移植质量；不消除球面对称性 | 基线完成后的优先 LIO 候选 |
| LIO-SAM ROS 2 分支 | 因子图 LIO 与回环路线 | 有明确的传感器接入与回环结构 | ring/time、IMU 姿态与频率要求；当前 100 Hz 配置不能直接照搬 | 备选，不作为首个接入目标 |
| 已知球面/结构标记辅助定位 | 缺特征区域的绝对锚点 | 能直接针对球罐歧义提供额外约束 | 先验精度、标记可见性与实际布设条件 | 自然特征不足时优先补观测 |

RTAB-Map 的 ROS 2 启动源码分别提供 RGB-D 与 ICP 里程计接入入口，适合做可比较的
基线；这并不代表两者都已适配当前插件。[RTAB-Map ROS 2](https://github.com/introlab/rtabmap_ros/tree/ros2)、
[启动源码](https://github.com/introlab/rtabmap_ros/blob/ros2/rtabmap_launch/launch/rtabmap.launch.py)

FAST-LIO 上游说明支持 Velodyne、外部 IMU，并强调同步和逐点时间；上游主线安装说明
仍以 ROS 1 为主。实施前必须选定并验证 ROS 2/Humble 的具体移植版本和提交，
不能把上游功能说明当作当前工作区的即装即用保证。基础 LIO/增量地图也不等于已经具备
完整全局回环和重定位。[FAST-LIO 上游](https://github.com/hku-mars/FAST_LIO)

LIO-SAM 的 ROS 2 分支文档要求检查 ring 和逐点时间，并说明其 IMU 姿态假设，建议
至少 200 Hz。当前车体 IMU 为 100 Hz，且真实硬件未定型；不能用仿真提供的理想姿态
绕过真实硬件限制。[LIO-SAM ROS 2 说明](https://github.com/TixiaoShan/LIO-SAM/tree/ros2)

**当前推荐决策：先完成 RTAB-Map 的独立 ICP/RGB-D 基线，不同时融合两个里程计；
后续若雷达观测有效而动态误差突出，再评估 FAST-LIO2。若主要失败来自球面对称性，
优先增加可观测信息，不能指望单纯升级 LIO 解决。**

不优先使用面向平面地图的 2D SLAM 作为整罐六自由度定位方案。需要二维巡检展示时，
后续可把三维结果投影到球面经纬/分片展开图，但投影图不代替三维状态估计。

## 6. TF 与真值隔离设计

### 6.1 当前显示阶段

```text
world --Gazebo真值--> base_link
                         ├── lidar
                         ├── imu_link
                         └── 机械臂关节链 → arm_flange → D435i
```

先用 world 显示运动，不引入新的位姿发布者。

### 6.2 后续估计模式

```text
map --建图/定位后端--> odom --唯一里程计发布者--> base_link → 各传感器

world --Gazebo真值--> base_gt     （可选，仅用于评估/画轨迹）
```

`odom` 作为连续但可漂移的局部参考；`map → odom` 表达回环/全局定位修正。
TF 每个子帧只能有一个父帧，不允许真值和估计器同时发布 base_link 的位姿。
[ROS REP-105](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-0105.rst)

后续实施时需要：

1. 给现有驱动增加可配置的真值话题/TF 开关，建议真值改名为 `/ground_truth/odom`；
   估计模式关闭其 `world → base_link`。现在尚未添加这些开关。
2. 仅选一个前端发布 `odom → base_link`。候选算法若输出 IMU/lidar 位姿，应通过
   正确外参转换后接入；多个算法对比时输出到独立话题，不争抢 TF。
3. 后端发布 `map → odom`；前端不随回环跳变。没有后端时只用 odom，或在明确初始化
   约定下使用固定 map→odom，不能把它当作已获得全局定位。
4. 真值只进日志、误差计算、独立轨迹显示。禁止根据真值实时修正 world→map，再宣称
   是自主定位；离线误差评估的刚体对齐也不能回灌估计器。
5. 当前 MoveIt 用 world 根帧和预先生成的罐体障碍。接估计 TF 时须同步设计
   world/map 的注册关系，或让规划场景转到 map 根帧，避免罐壁与机器人错位。
   无已知注册关系时，不能随意发布单位 world→map。

真值地图、已知 CAD 先验、传感器重建地图要分别保存。利用已知球罐尺寸定位是
“先验地图辅助定位”的实验，不是从零建图；MoveIt 的轻量罐壁 STL 也不是 SLAM 结果。

## 7. 分阶段任务与验收

### 阶段 A：显示、数据与评估基准

- 后续建立独立定位 RViz 配置，Fixed Frame=world；MoveIt 的近距离操作视角可保留。
- 静止、低速行走、转弯、倾斜分别录包：点云、RGB、depth、所有 CameraInfo、两路 IMU、
  joint_states、tf/tf_static、clock、控制指令和单独保存的真值。
- 所有仿真节点 use_sim_time 一致；检查时间戳、QoS、掉帧与 TF 在消息时间点是否可用。
- 审计激光逐点时间。如果仿真一帧是在同一时刻采样，就按瞬时扫描处理；不能为了满足
  LIO 字段要求按方位角伪造时间，再对本来无畸变的点云做去畸变。
- 审计 IMU 的 orientation：Gazebo 当前可输出世界参考姿态。与真实六轴 IMU 比较时，
  要区分“只用 gyro/accel”与“使用理想姿态”的实验，防止无意泄露真值。
- RGB-D 先检查配准：相同分辨率和帧率不表示像素已经对应。

产物：可重复回放的数据包、传感器接口清单、时间/TF 检查报告、独立真值轨迹。

### 阶段 B：单传感器里程计基线

- 机械臂保持固定，先在有独特特征的地面场景测试 3D ICP，再单独测试 RGB-D。
- 过滤雷达/深度中的自体点：包括车体、磁轮、支架和机械臂；移动关节的自体过滤需
  使用相应时刻 TF。传感器本身跟着机器人走的结构不是环境地标。
- 初始不启用回环，不加复杂融合，分别记录 odometry、Path、耗时和失败标志。
- 最后移到半球，再到完整球；报告场景差异，而不只展示最好看的轨迹。

产物：两种基线的误差曲线、失败场景与选型结论。

### 阶段 C：LIO 或额外环境约束

- 若主要问题是运动畸变/短时姿态漂移，验证选定的 ROS 2 LIO 实现，标定 lidar↔imu，
  再按真实硬件能力评估 IMU 频率，而非直接采用更理想的仿真配置。
- 若主要问题是几何退化，增加非对称结构/视觉标记对照实验，考虑球面约束和轮速弱约束。
- 不把已经使用过同一 IMU 的 LIO 输出与该 IMU 简单重复融合并视为独立信息。
- 钢壁/磁轮现场的磁场、反光、粉尘、遮挡等影响需要实物验证，不能由 Gazebo 成功推出。

产物：固定版本的候选算法、外参与时间配置、退化检测与失效处理说明。

### 阶段 D：建图、回环与已有地图定位

- 从局部点云地图开始，按关键帧/体素融合，限制地图体积和发布频率。
- 再启用回环：检查回到旧位置后是否真正一致，尤其防止重复焊缝的错误闭环。
- 保存点云与后端所需的关键帧/数据库/位姿图。单独一个 PCD 不一定能恢复算法的
  重定位状态；保存地图和“关闭程序后重新定位成功”是两个验收项目。
- 初步地图：三维几何点云；随后增加彩色表面和焊缝/缺陷位置，最后才考虑导航表征。
- 另做真值位姿融合地图作为传感器覆盖率上限对照，明确标为真值基准地图。

产物：地图文件、可重启的定位流程、闭环前后误差、覆盖率和重复表面厚度评估。

### 阶段 E：机械臂扫动与巡检融合

- 首先保持底盘静止、只动机械臂；按时间同步的运动学变换把相机数据投到地图。
- 雷达/车体 IMU 提供车体状态，相机优先补充局部彩色/深度与缺陷信息。
- 再验证车臂同时运动、动态外参和测量不确定性；不直接套用固定外参 LIVO 配置。
- 将巡检点定位精度与地图视觉效果分开验收。

## 8. 建议验收指标（待首轮数据校准，不是性能承诺）

| 维度 | 初始检查方式/建议门槛 |
|---|---|
| 轨迹精度 | 有特征场景 10 m 路径：位置 ATE RMSE 暂以 ≤0.10 m、终点位置漂移 ≤路径长 1% 为目标；单列姿态误差 |
| 误差计算 | 对齐时间戳、统一 base_link 测量点；用一次 SE(3) 刚体对齐去掉初始坐标差，禁止逐帧对齐或缩放掩盖漂移；同时报 RPE |
| 鲁棒性 | 同一路径至少重复三次；统计丢跟踪、重初始化、错误回环；光滑球面允许得到“观测不足”的结论 |
| 地图质量 | 查看重复表面/墙厚、覆盖率、回环接缝；不能只看拟合半径是否接近 3 m |
| 实时性 | 记录算法 P95 耗时与输入周期、队列是否增长、仿真实时倍率；定位 RViz 先以 ≥20 FPS 为显示目标 |
| 运动类型 | 球底、斜壁、竖壁、倒挂分别验证；不能只在水平地面通过后宣称可爬满球罐 |
| 相机补偿 | 底盘静止而机械臂扫动时，恢复的底盘位姿应保持不动；先排查同步再讨论精度阈值 |

性能策略：定位显示与机械臂操作显示分开；累计地图低频发布、体素降采样，
只绘制必要的局部点云。不要重现“每帧把整罐高密度网格送入 RViz 重建”的问题。

## 9. 开始实施前的少量待定项

1. 实际使用完整封闭罐还是开口罐？是否有可识别管口、内构件或允许布设标记？
2. 实物雷达型号与 IMU 型号、可用频率、同步接口是什么？仿真 VLP-16 不代表最终硬件。
3. 优先目标是厘米级巡检点复访，还是先完成粗定位和三维覆盖地图？
4. 行走时能否固定机械臂？本草案默认可以；若必须持续扫动，动态外参工作应提前。

在这些信息未确定前，仍可开展阶段 A 和阶段 B 的离线基线工作；本轮仅保存方案。
